# KFM

Репозиторий проекта: [Meierbek/KFM](https://github.com/Meierbek/KFM).

Первый запуск на другом компьютере и совместная работа через GitHub описаны в [CONTRIBUTING.md](CONTRIBUTING.md). Репозиторий содержит код и учебные изображения. Видео, разметка, реальные результаты анализа, ключи, программы и веса моделей остаются локальными. Свежая копия запускает сайт и деморежим без подключения модели.

Локальное приложение для проверки кассовых операций по видео. Работают загрузка MOV и MP4, просмотр записи, страница результатов, история последних восьми проверок и два демонстрационных сценария. Подготовлены несколько экспериментальных анализаторов для локальной Ollama. Платные сервисы и отдельный сервер для работы на этом компьютере не нужны.

**Улучшения точности добиться не удалось.** На одних и тех же 13 отложенных видео новая схема с Qwen3-VL 4B дала 5 правильных ответов, базовая схема с 2B — 7. При этом 2B назвала нарушением все 13 видео, поэтому её результат тоже ненадёжен. Новая схема 4B не активирована; в сайте остаётся экспериментальная Qwen3-VL 2B Instruct. Полные результаты и ограничения — в [QUALITY_REPORT.md](QUALITY_REPORT.md). Деморежим и программные тесты не подтверждают точность распознавания.

Qwen3-VL 8B Instruct загружена, но не активирована. Единственная контролируемая попытка загрузки для проверки на искусственном изображении остановлена через 12,4 секунды: свободный резерв памяти Windows (commit) снизился до 1,606 GiB при защитном пороге 2 GiB. Модель не вернула ответа; видео набора через 8B не запускались, точность не проверена. Этот результат относится к состоянию данного компьютера во время попытки и не доказывает невозможность запуска на другом оборудовании.

## Запуск

На этом компьютере откройте `START_KFM.cmd` двойным щелчком. Браузер откроется автоматически. В терминале также появится адрес:

**http://127.0.0.1:8765**

Файл запуска сам поднимает локальную Ollama и открывает браузер. Терминал KFM должен оставаться открытым. Для остановки сайта нажмите Ctrl+C в терминале. Повторный запуск сохраняет ранее загруженные записи. Процесс Ollama остаётся в фоне для следующего запуска.

Сайт использует Python 3.10 или новее и его стандартную библиотеку. На этом компьютере файл запуска находит уже установленный Python Codex. Ollama, FFmpeg и веса модели сохранены в `.tools/` и `.models/`. Интернет использовался для первоначальной загрузки программ и весов; при анализе записи обрабатываются локально, облачный режим Ollama отключён. Автоматический разбор Excel-разметки дополнительно использует уже установленный openpyxl.

Для запуска вручную:

```powershell
python server.py
```

## Что попробовать

1. Откройте «Деморежим», выберите сценарий с возможными нарушениями и нажмите «Открыть демонстрацию».
2. После обработки откройте событие на 00:12 или 00:27. Кнопки с таймкодами перемещают учебный плеер. Нажатие на кадр открывает его крупно.
3. Вернитесь к новой проверке и выберите сценарий без нарушений.
4. В режиме «Ваше видео» выберите MOV или MP4 размером до 128 МБ. Файл обработает экспериментальная локальная модель. При неоднозначности будет показано, что результат не получен.

Демонстрация независима от пользовательских видео: сцены нарисованы, события заданы заранее, источники обозначены как учебные. Они не являются анализом реальной записи или юридическим заключением.

Некоторые кодеки MOV, например отдельные варианты HEVC или ProRes, могут не воспроизводиться браузером. Загрузка файла при этом сохраняется; для просмотра используйте локальный видеоплеер либо MP4/H.264. Автоматическое перекодирование пока не реализовано.

## Доступные локальные анализаторы

Новый вариант `refined_model.py` сначала просматривает окна до 24 секунд с перекрытием 3 секунды: по девять кадров на окно. Затем повторно проверяет предполагаемые события по более плотной последовательности кадров вокруг найденного момента. `visual_sampling.py` сохраняет пропорции изображения, в том числе у вертикального видео. Кадры передаются модели через локальную Ollama на `127.0.0.1:11434`.

Для каждого события модель отдельно отвечает на обязательные вопросы: признак присутствует, отсутствует или неясен. Событие принимается только при подтверждении всех необходимых признаков. В результат входят таймкод, описание, нормативное основание и 1–3 исходных JPEG-кадра. Реализованы проверки трёх типов:

- **Личные вещи сотрудника в кассовой зоне — пункт 12.** Нужно различить вещь, её принадлежность сотруднику и размещение в кассовой зоне, а также исключить разрешённые предметы и банковское оборудование. Само наличие телефона или сумки в кадре недостаточно.
- **Уход кассира до окончания обслуживания — пункт 22.** Пункт относится к операциям приёма наличных. Требуется видимый уход от рабочего места при незавершённом обслуживании остающегося клиента. Поворот, вставание и работа с соседним устройством сами по себе не подтверждают нарушение.
- **Деньги предыдущей операции вне хранения — пункт 20.** Требуется проследить завершение предыдущей операции, начало следующей и оставшиеся деньги. Деньги текущего клиента на рабочем столе сами по себе не являются основанием.

В `rules.json` девять нормативных оснований из [постановления НБРК № 231](https://adilet.zan.kz/rus/docs/V1900019680), редакция от 16.03.2026; локальные тексты — в `local_review/legal/`. Автоматические проверки новой схемы ограничены тремя указанными типами. По редким кадрам нельзя устанавливать отсутствие пересчёта, подписи или выдачи документа: действие могло происходить между кадрами или вне обзора. Звуковая дорожка и распознавание личности не используются.

Поддерживаются записи до пяти минут; бюджет работы нового анализатора — около 270 секунд. Неполный проход, плохая видимость, ошибки ответа или неразрешённые сомнения при отсутствии подтверждённых событий дают `failed` с `verdict: null`. Если часть событий подтверждена, число оставшихся неясных кандидатов сохраняется в `analysis.unresolved_candidates`. Полный проход по плану выборки не означает просмотра каждого кадра и не гарантирует, что короткое действие не пропущено. Параллельные запросы к одной видеокарте замедляют обработку.

**Дополнительный вариант с поиском предметов.** `object_model.py` использует `yolo_candidates.py`: локальный YOLOv8n на CPU ищет сумки, рюкзаки, бутылки, чашки и телефоны примерно раз в четыре секунды (`confidence=0.3`, `imgsz=960`). До двух предложенных фрагментов с увеличенной областью предмета передаются той же проверке признаков с окружающим контекстом в дополнение к общему обзору. Оценка детектора означает уверенность в обнаружении предмета, а не вероятность нарушения; принадлежность, кассовую зону и исключения всё ещё нужно подтвердить. Это отдельный экспериментальный вариант. Условия лицензии YOLO указаны в `YOLO_NOTICE.md`.

**Эксперимент DINOv2 не активирован.** На CPU извлекались признаки замороженного DINOv2-small каждые две секунды и обучались небольшие классификаторы восьмисекундных окон. Проверка использовала пять групповых разбиений по SHA-256 видео; признаки одного файла не попадали одновременно в обучение и проверку. Лучший из 32 вариантов на dev дал сбалансированную точность **63,2%** и полноту **57,1%**: 8 верных обнаружений, 9 верных отрицательных ответов, 4 ложных срабатывания и 6 пропусков. Настройки и порог выбирались по этим же проверочным прогнозам, поэтому оценка оптимистична; это не результат holdout. Качества недостаточно для включения в основной путь. Сравнение сохранено в `local_review/visual_baseline_tuning/`; прежние веса сохранены отдельно, новая версия весов не выпущена.

**Gemma с отдельными кадрами не активирована.** `sequence_model.py` передаёт модели Gemma 3 4B до девяти отдельных кадров с номерами и временем, сохраняя ту же проверку необходимых признаков. Проверка совместимости с локальной Ollama прошла, но пробный прогон четырёх dev-видео дал один пропуск и три неопределённых результата, без правильных окончательных ответов. Этот вариант сохранён для исследований, а не выбран для рабочего режима. Источники, точные версии и лицензии всех загруженных моделей перечислены в [MODEL_NOTICES.md](MODEL_NOTICES.md).

**Активная экспериментальная схема и её история.** `local_model.py` использует Qwen3-VL 2B Instruct, окна по 12 секунд с шагом 10 секунд и пять кадров на окно. Первый пробный прогон на пяти выбранных коротких видео закончился пятью отказами от вердикта. После исправления формата ответа повторный прогон дал **2 совпадения из 5**: оба положительных примера найдены, все три отрицательных получили ложное срабатывание. Время — 35–77 секунд при параллельном пакетном разборе. Это исторический малый пилот; он не заменяет завершённое ниже сравнение на 13 видео. Старые отчёты: `local_review/benchmark_summary.json` и `local_review/benchmark_summary_v1.json`.

## Автоматическая таблица обучающих видео

Готовые локальные файлы: `local_review/video_review.html` и `local_review/video_review.csv`. В таблице есть видео, метка организаторов, размеченный таймкод, секунды выбранных кадров, описание модели, предполагаемый тип и правило для проверки. Противоречащие типу ссылки исключаются. Это предварительные машинные наблюдения, а не подтверждённая разметка.

Для положительных примеров выбираются пять кадров вокруг таймкода из `open_labels.xlsx`, для отрицательных — шесть кадров по длительности записи. Модель не получает метку ответа, но выбор кадров использует разметку: такой проход нельзя считать независимым тестом точности. Скрипт `review_dataset.py` сохраняет промежуточные результаты и продолжает с последнего сохранённого ролика. Кадры и описания остаются в `local_review/` на этом компьютере и не отправляются облачной модели.

## Проверка качества и воспроизводимость

Завершено сравнение схем на одной выборке из 13 видео. Refined + 4B: 5 верных обнаружений, 4 ложных срабатывания, 2 пропуска и 2 отказа; правильных отрицательных ответов нет. Legacy + 2B: 7 верных обнаружений и 6 ложных срабатываний, то есть ответ «нарушение» на каждом видео. Сбалансированная точность с учётом отказов — **35,7% против 50,0%**; доля правильных ответов среди всех запусков — **38,5% против 53,8%**. Это не улучшение, поэтому refined 4B не включена в сайт. Базовый прогон использовал текущий общий справочник правил, включая пункт 22; это не побайтовая копия первоначального приложения.

Агрегированный отчёт: [QUALITY_REPORT.md](QUALITY_REPORT.md). Исходные агрегаты: `local_review/evaluation/refined-4b-holdout-v8/summary.json` и `local_review/evaluation/legacy-2b-holdout-v1/summary.json`. Пилоты Gemma и YOLO на четырёх dev-видео приведены отдельно и не включены в итоговую оценку. Сохранение 2B означает только отсутствие подтверждённой замены, а не достаточную точность для конкурсного решения.

В исходных 42 файлах обнаружены две группы побайтовых дубликатов. Исправленный манифест `local_review/evaluation_split_deduplicated.json` содержит **40 уникальных видео: 27 dev и 13 holdout**. В dev — 14 положительных и 13 отрицательных примеров; в holdout — 7 и 6. Разделение фиксировано до последующей настройки: все ранее использованные dev остались в dev, дубликаты объединены по SHA-256, для положительного дубликата сохранены оба размеченных момента. Исходный манифест сохранён для аудита в `local_review/evaluation_split.json`.

Для завершённого сравнения dev использовалась при разработке, а holdout — после фиксации настроек. Отложенная часть не является внешней независимой выборкой: это тот же небольшой набор организаторов, ранее проходивший локальную предварительную разметку. Результат на нём не доказывает работу на других камерах и любых неизвестных нарушениях. Последующие решения, включая попытку запуска 8B, уже принимались после знакомства с результатами holdout. Повторный прогон на тех же 13 видео будет исследовательским внутренним сравнением, а не новой независимой проверкой.

`evaluate_dataset.py` передаёт живому анализатору нейтральную копию `input.mov` и метаданные контейнера. Метка, исходное имя файла, размеченный таймкод и ранее полученный вердикт не передаются. Сравнение с разметкой происходит после ответа. Отчёт отдельно учитывает ложные срабатывания, пропуски, отказы и долю успешно обработанных видео; сохраняет precision, recall, F1, balanced accuracy, долю верных ответов среди всех запущенных примеров, включая отказы, и время работы. Проверка таймкода по умолчанию допускает отклонение ±5 секунд. Бинарная разметка не проверяет правильность типа события и юридической ссылки.

Команды выполняются из папки `kfm`. Имя модели ниже — пример воспроизводимого эксперимента, а не указание текущей конфигурации сайта:

```powershell
python evaluate_dataset.py --prepare-only --split dev --output local_review/evaluation/prepared
python evaluate_dataset.py --split dev --limit 4 --analyzer refined --model qwen3-vl:4b-instruct --output local_review/evaluation/refined-dev-example
```

Команда полного прогона без ограничения числа примеров приведена ниже. Она запускает текущий код; версии исходников завершённых прогонов сохранены в их `source_snapshot/`. Повторное использование этой же выборки после доработок должно быть явно отмечено в отчёте:

```powershell
python evaluate_dataset.py --split holdout --analyzer refined --model qwen3-vl:4b-instruct --output local_review/evaluation/refined-holdout-example
```

Для варианта с YOLO используется `--analyzer objects`, для прежнего анализатора — `--analyzer legacy`. `--limit` разрешён только на dev. Прерванный прогон можно продолжить с `--resume` и теми же аргументами: скрипт сверяет отпечатки кода, модели, конфигурации, весов и разделения. После изменения реализации используйте новую папку отчёта. `summary.json` и `report.md` содержат агрегированные показатели; подробные ответы, кадры и трассировки остаются локальными и не предназначены для отправки облачному AI.

`.qa/write_accuracy_report.py` собирает сравнение только из `summary.json` и проверяет совпадение набора, разбиения, справочника правил и полный проход по 13 видео. Для кандидата, выбранного или доработанного после знакомства с предыдущими результатами holdout, обязателен флаг `--post-holdout-development`; он добавляет явное предупреждение о повторном использовании набора. Для завершённого сравнения 4B и 2B такой флаг не применялся.

## Замена модели

Интерфейс не обращается к модели напрямую. Сервер вызывает анализатор через общий интерфейс `analyzers.py`. Встроенные варианты выбираются через `KFM_ANALYZER` в `.env`: `refined`, `objects`, `sequence`, `large` или прежний `ollama`; имя модели Ollama задаётся в `KFM_OLLAMA_MODEL`. Сейчас сохранён `ollama` с Qwen3-VL 2B Instruct. Refined 4B, YOLO, Gemma и исследовательский `guided` с DINO не включены в основной путь: улучшение не подтверждено. Загруженная 8B и её анализатор `large` также не активированы: попытка загрузки прервана защитой по памяти до получения ответа; точность на видео не измерялась.

Другую реализацию можно подключить двумя способами:

1. Реализовать собственный класс на основе `Analyzer` и выбрать его в `App.__init__` файла `server.py`.
2. Запустить отдельную локальную программу-обёртку модели и указать её HTTP-адрес в `.env`.

Для второго способа скопируйте `.env.example` в `.env` и задайте:

```dotenv
KFM_ANALYZER_URL=http://127.0.0.1:9000/analyze
KFM_MODEL_NAME=Название вашей локальной модели
```

Перезапустите KFM. Адрес должен принадлежать loopback-интерфейсу того же компьютера. Эта настройка означает, что анализатор настроен; его реальная доступность проверяется при обработке задания.

Это **адрес вашей обёртки, а не готовый endpoint Ollama или vLLM**. Обёртка должна сама декодировать видео, выбирать кадры с реальными временами, обращаться к локальной модели, сопоставлять наблюдения с проверенными правилами и извлекать JPEG-кадры. Простого указания имени модели недостаточно.

KFM отправляет обёртке POST с JSON:

```json
{
  "video_path": "C:/absolute/path/to/uploaded.mov",
  "metadata": {
    "duration_sec": 42.0,
    "width": 1920,
    "height": 1080,
    "size_bytes": 1024000
  },
  "rules": []
}
```

Ответ обёртки:

```json
{
  "verdict": "violation",
  "violations": [
    {
      "type": "Название наблюдаемого события",
      "timecode_sec": 12.4,
      "description": "Что видно и почему это может указывать на нарушение",
      "evidence_frames": [
        { "timestamp_sec": 12.4, "image_base64": "BASE64_OF_ACTUAL_JPEG" }
      ],
      "rule": {
        "title": "Проверенное название документа",
        "section": "Пункт или раздел",
        "url": "https://adilet.zan.kz/..."
      }
    }
  ]
}
```

При отсутствии событий возвращаются `verdict: "no_violation"` и пустой `violations`. Для нового встроенного анализатора это означает отсутствие найденных событий только трёх поддерживаемых категорий в выбранных кадрах. `rule` — расширение для интерфейса KFM; нормативный источник также включается в `description`. В `rules.json` сохранены проверенные ссылки и ограничения применимости. Для включения отдельной HTTP-обёртки уберите переменную `KFM_ANALYZER` из `.env`, чтобы встроенный вариант не имел приоритета.

Сервер проверяет два допустимых вердикта, согласованность списка событий, конечные неотрицательные таймкоды и 1–3 JPEG-кадра на событие. Некорректный ответ модели завершает задание ошибкой, а не чистым вердиктом. Тайм-аут обращения к локальному анализатору — 250 секунд; предельное время всего решения всё равно нужно измерить на реальных видео и нагрузке жюри.

## API для жюри

Ключ создаётся при первом запуске и хранится в `data/api_key.txt`. Он не включается в клиентский JavaScript. Альтернативно задайте `KFM_API_KEY` через окружение или `.env`.

Основные маршруты требуют заголовок `X-API-Key`:

```powershell
curl.exe -X POST http://127.0.0.1:8765/api/v1/analyze `
  -H "X-API-Key: YOUR_KEY" -F "file=@C:/path/video.mov"

curl.exe http://127.0.0.1:8765/api/v1/jobs/JOB_ID `
  -H "X-API-Key: YOUR_KEY"
```

Первая операция возвращает HTTP 202 и `job_id`. Вторая возвращает `processing`, `done` или `failed`. Если модель недоступна или не может обосновать результат, задание завершается `failed`, с `verdict: null` и пустым `violations`. Это **не** означает отсутствия нарушения.

Учебный API доступен отдельно: `POST /api/v1/demo`, JSON `{"scenario":"violation"}` или `{"scenario":"clean"}`. Результаты всегда содержат `demo: true`.

Браузер использует отдельные `/ui/api/` маршруты с локальной HttpOnly-сессией. Они не заменяют ключ на `/api/v1/`. Видео поддерживает HTTP Range для перемотки.

## Файлы и локальность

- `static/` — страницы, стили, JavaScript, ваш логотип и учебные иллюстрации.
- `server.py` — локальный сервер, загрузка, очередь и API.
- `analyzers.py` — граница подключения модели и демонстрационный анализатор.
- `local_model.py` — активная экспериментальная схема 2B, также использованная как базовая при сравнении.
- `refined_model.py`, `visual_sampling.py` — обзор видео и повторная проверка признаков события.
- `object_model.py`, `yolo_candidates.py` — дополнительный поиск предметов и проверка увеличенных фрагментов.
- `sequence_model.py` — эксперимент с отдельными кадрами для Gemma, не включённый в основной путь.
- `large_model.py` — экспериментальный анализатор для 8B, не активированный после остановленной попытки загрузки.
- `visual_baseline.py`, `train_visual_baseline.py`, `guided_model.py` — неактивированный эксперимент DINO и его обучение только на dev.
- `evaluate_dataset.py` — воспроизводимая оценка по фиксированному разделению данных.
- `QUALITY_REPORT.md` — завершённое сравнение 4B и 2B на 13 видео с отдельными исследовательскими пилотами.
- `rules.json` — девять нормативных оснований с условиями и исключениями.
- `local_review/` — автоматическая таблица, локальные кадры, тексты правил и измерения качества.
- `.tools/`, `.models/` — установленные программы и веса модели.
- `.ml-deps/`, `.yolo-deps/` — изолированные дополнительные Python-зависимости для локальных экспериментов.
- `data/uploads/` — загруженные видео под случайными идентификаторами.
- `data/jobs.sqlite3` — состояния заданий и результаты.
- `data/api_key.txt` — ключ API.

Ядро сервера использует стандартную библиотеку Python; новая обработка кадров дополнительно требует Pillow. Эксперименты DINO и YOLO используют локальные CPU-версии PyTorch и дополнительные библиотеки из указанных папок. Они уже установлены на этом компьютере; это не встроенные компоненты Python.

Загрузка, просмотр и анализ не отправляют видео, кадры и их описания в сторонние сервисы. Интернет нужен для первоначального получения программ и весов; сами модели работают локально. Пакетный скрипт читает исходную папку `open/videos`; сайт обрабатывает выбранную пользователем запись. По умолчанию сервер слушает только `127.0.0.1`; публичный доступ для финальной проверки пока не настроен. Завершённая проверка на 13 видео показала недостаточное качество. Для конкурсной сдачи ещё нужны подтверждённое улучшение на новых независимых данных, нагрузочный замер и согласованный доступ для жюри.

Для удаления локальной истории сначала остановите сервер, затем самостоятельно удалите папку `data`. Это также удалит видео и текущий API-ключ. Файлы `data/`, `.env` и вспомогательная папка `.qa/` исключены из Git.

## Проверка реализации

```powershell
python -m unittest discover -v -p "test_*.py"
```

Тесты используют синтетические данные и временные папки. Они проверяют API, локальную сессию, демосценарии, загрузку, Range, форматы ответов, запрет облачного адреса, обработку неопределённости, выборку кадров, проверки признаков, расчёт метрик и защиту разделения данных от утечки. Это проверка программы, а не измерение точности на реальных записях и не визуальная проверка интерфейса.

17 октября 2026 года прошли **92 из 92** программных тестов; проверка синтаксиса `static/app.js` также прошла. Это не подтверждает точность распознавания. Визуальная проверка интерфейса в автоматическом браузере в этом запуске была недоступна.

Отдельно после перезапуска работающего приложения успешно прошли проверка доступности (health) и **оба синтетических демосценария**. Проверены запуск сайта и демонстрационный путь; качество анализа реальных видео оценивается приведённым выше сравнением.
