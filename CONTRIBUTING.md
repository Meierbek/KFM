# Совместная работа над KFM

## Доступ другу

Проект находится в [Meierbek/KFM](https://github.com/Meierbek/KFM). Откройте [настройки доступа](https://github.com/Meierbek/KFM/settings/access): **Settings → Collaborators → Add people**, укажите GitHub-логин друга и отправьте приглашение. Друг должен принять его в своём аккаунте. После этого у каждого будет своя копия проекта и возможность отправлять изменения.

Приглашение и приватный репозиторий доступны на GitHub Free. Инструкция GitHub: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository

## Первый запуск на другом компьютере

Понадобятся Git и Python; для разработки проверена версия **Python 3.12**. Откройте терминал в папке, где хотите сохранить проект:

```powershell
git clone https://github.com/Meierbek/KFM.git KFM
cd KFM
python server.py
```

Откройте **http://127.0.0.1:8765**. На Windows также можно открыть `START_KFM.cmd`. Свежая копия запускается без модели: работают сайт, загрузка видео, история и учебные демосценарии. Автоматический анализ появится после отдельной настройки локального анализатора.

У каждого разработчика свой локальный сервер, свои загруженные записи и API-ключ. Адрес `127.0.0.1` открывает сайт только на том компьютере, где запущен сервер.

Скачанные Ollama, FFmpeg и веса моделей не включены в репозиторий. Копирование кода не переносит готовую модель с первого компьютера. Настройка анализаторов описана в README.md; измеренное качество — в QUALITY_REPORT.md. Не включайте 8B на этом компьютере без отдельной проверки ресурсов: пробная загрузка была остановлена монитором памяти.

## Как внести изменение

Начинайте каждую задачу с актуальной основной ветки. Пример для изменения загрузки видео:

```powershell
git switch main
git pull --ff-only
git switch -c feature/video-upload
```

Измените нужные файлы, проверьте сайт и просмотрите список изменений:

```powershell
git status
git diff
git add static/app.js
git commit -m "Improve video upload"
git push -u origin feature/video-upload
```

В `git add` указывайте файлы своей задачи. На GitHub нажмите **Compare & pull request**, опишите изменение и попросите второго участника проверить его. После проверки выполните **Merge pull request**. Перед следующей задачей снова обновите `main`.

Если Git при первом коммите попросит имя и почту, задайте их только для этого проекта:

```powershell
git config user.name "Ваше имя"
git config user.email "Ваша почта GitHub или noreply-адрес GitHub"
```

Не используйте `git push --force` для общей `main`. Если изменение затрагивает те же строки, сначала согласуйте правки и разрешите конфликт в своей ветке.

## Проверка кода

В виртуальном окружении Python 3.12 установите зависимости и запустите синтетические тесты:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -v -p "test_*.py"
```

На macOS/Linux используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. Тесты создают искусственные данные и подменяют ответы моделей. Они не требуют конкурсных видео, Ollama, весов моделей или GPU и не измеряют точность распознавания.

Если установлен Node.js, дополнительно выполните `node --check static/app.js`. Проверки автоматически запускаются в GitHub Actions при отправке изменений и создании pull request.

## Какие файлы остаются локальными

`.gitignore` исключает `.env`, `data/`, `local_review/`, `.qa/`, программы, веса, зависимости, типичные видеофайлы, таблицы разметки, базы данных и логи. В репозитории остаются код, правила, документация, логотип и нарисованные учебные изображения.

Данные конкурса и результаты реальных проверок передавайте только разрешённым организаторами способом. Даже приватный GitHub-репозиторий не является локальным хранилищем. `.gitignore` защищает обычный `git add`, но не отменяет явное принудительное добавление; не используйте `git add -f` для исключённых данных.
